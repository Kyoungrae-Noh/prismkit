## 이전 중단과 이번 승인

[이전 사전 검증](PHASE2B_PREFLIGHT.md)은 비용 조건 불명확으로 실제 호출 전 중단한 기록이다. 이후 사용자가 비용의 불확실성을 인지하고 최소 1회 읽기 전용 검증을 승인했다. 이번에는 `온누리상품권` GET 1회만 실행했고, 추가 실제 호출은 하지 않았다. 결제·광고 집행·계정 설정 변경은 하지 않았다.

`.env`와 검색광고 인증 변수 3개의 존재, Git 무시 및 미추적 상태를 확인했다. 비밀값을 출력하지 않았다. 기존 `.env.example`, Phase 2A 안내와 이전 Phase 2B 중단 문서를 그대로 보존했다.

## 실제 응답

| 항목                             | 확인 결과                                         |
| -------------------------------- | ------------------------------------------------- |
| 메서드/엔드포인트                | GET `https://api.searchad.naver.com/keywordstool` |
| 요청 키워드                      | 온누리상품권                                      |
| 실제 호출 수                     | 1회, 자동 재시도 없음                             |
| HTTP 상태                        | **200**                                           |
| 응답 수집 시각                   | 2026-10-19T10:24:17.896Z (한국 시각 19:24:17)     |
| 최근 30일 PC 검색량              | **38,100**                                        |
| 최근 30일 모바일 검색량          | **152,400**                                       |
| 합계                             | **190,500**                                       |
| 응답 키워드 행                   | 515개                                             |
| 핵심 키워드 제외 연관어          | **514개**                                         |
| PC 또는 모바일에 `<10`이 있는 행 | 142개                                             |

`keywordList`, `relKeyword`, `monthlyPcQcCnt`, `monthlyMobileQcCnt`를 실제 응답에서 읽어 정규화했다. 숫자/문자열 숫자 및 `<10`은 별도로 처리한다. 원시 응답 전체는 파일·브라우저 저장소에 저장하지 않았으며 키나 인증 헤더를 로그에 남기지 않았다. 이 표는 당시 검증 기록이며 현재 시점 수치로 자동 갱신하지 않는다.

검색광고의 연관 키워드는 네이버 검색창 자동완성이나 검색화면 연관검색어와 다른 데이터다. 인증/응답 정규화 성공에 근거해 검색광고만 VERIFIED로 표시했다. API HUB에는 요청하지 않았다.

## 구현 기능

- Node 기반 로컬 백엔드: 고정 GET 조회, HMAC-SHA256 서명, 서버 전용 환경변수, 안전한 오류 응답.
- 기존 SearchVolumeProvider/KeywordExpansionProvider 계약을 구현한 로컬 API 클라이언트. 검색량·관련어·출처·조회 시각·검증 상태·누락 정보 전달.
- 키워드 입력 및 명시적 조회 버튼, PC/모바일/합계, 관련 키워드 표, PC·모바일·합계 정렬, 출처·시각, 오류 표시.
- 결과 검증 성공 시에만 LIVE 표시. 실패 시 이전 LIVE 결과 제거. 입력창을 수정하더라도 결과에는 마지막 조회 키워드를 별도로 표시.
- 표는 정렬 후 상위 50개를 표시한다. 서버 응답에는 전체 반환 목록이 포함된다. 결측·범위값은 정확한 숫자로 바꾸지 않고 정렬 마지막에 둔다.
- 기존 DEMO 및 MANUAL 저장·수정 기능 유지. 실제 자료는 영구 저장하지 않는다.
- 5분 메모리 캐시, 최소 10초 간격, 동시 요청 1개, 프로세스당 외부 호출 최대 10회. 인증 401/403 또는 429 이후 외부 호출 차단. 모든 오류에 자동 재시도 없음.
- 로컬 서버는 127.0.0.1만 사용하며 Host·Origin·고정 요청 헤더를 확인한다. 파일 제공 및 공개 CORS 없음.

## 테스트와 보안

- 기존 33개 유지: 단위·통합 21개 + 브라우저 12개.
- 새 서버 테스트 **17개**: 서명, 수치/범위/누락 변환, 입력·응답 검증, 자격증명 누락, GET·헤더, 캐시/만료, 간격/총량/동시 제한, 401/403/429 차단, 네트워크·JSON 오류, HTTP 접근 경계.
- 새 브라우저 테스트 **3개**: 같은 흐름을 1440px·390px·320px에서 실행. 버튼 전 요청 없음, LIVE/범위값/정렬/출처시각/인증 오류/수동 기능 유지와 `.env` HTTP 403 확인.
- 합계 **53개** 기능 테스트 통과(추가 20개). 자동 테스트는 모의 응답만 사용하고 실제 API를 반복 호출하지 않았다.
- TypeScript 및 프로덕션 빌드 통과. `npm run test:secrets`는 가짜 키와 로컬의 실제 API Key/Secret이 클라이언트 산출물에 없는 것, VITE_ 키 주입 시 빌드 거부를 확인한다. 비밀값은 출력하지 않는다.
- 실제 로컬 API 서버 시작 후 키워드 없는 요청이 HTTP 400으로 차단되는 것을 확인했다. 이 확인은 네이버 호출을 발생시키지 않았다. 확인 후 서버 종료.

실패한 테스트를 삭제하거나 무시하지 않았다. 초기 테스트용 HTTP 요청 객체 타입 오류를 수정했다. 포트 바인딩의 sandbox 제한은 로컬 서버 실행 권한으로 해결했다. NO_COLOR 안내 및 의도한 `.env` 접근 차단 로그는 기능 오류가 아니다.

## 비용·한도와 한계

[공식 FAQ](https://github.com/naver/searchad-apidoc/wiki/FAQ)는 총 호출량 제한 없음과 동적 호출 속도 제한을 구별한다. Customer ID와 키워드 API의 IP 제한을 안내하며 고정 RPS를 보장하지 않는다. [키워드 도구 429 안내](https://naver.github.io/searchad-apidoc/notice/2020/12/18/notice/)에 따라 반복 요청을 피하도록 구성했다. 앱의 10초/10회 제한은 자체 제한이다.

별도 API 호출 과금 여부와 상업적 재사용·영구 저장 허용 범위는 여전히 확정하지 못했다. 이번 승인 범위의 로컬 요청만 구현했으며 영구 무료 또는 포괄적 이용 허용으로 해석하지 않는다. `SourceAudit.usageApproved`는 일반 운영 승인 기준으로 false를 유지한다. 기존 운영 연결 정책과 이번 사용자 승인 로컬 조회는 구별한다.

실제 인증 실패/429를 유발하는 추가 호출은 하지 않았다. 해당 처리는 모의 테스트로 검증했다. 캐시·호출 예산은 프로세스 메모리 기반이므로 재시작 시 초기화된다. 운영 분산 쿼터·사용자 인증·영구 저장·API HUB 연결은 미구현이며 이번 범위 밖이다.

## 실행 방법과 종료 상태

프로젝트 루트의 별도 터미널 두 개에서 실행한다.

```sh
# 터미널 1: .env의 검색광고 변수 3개를 서버에서만 로드
npm run dev:api

# 터미널 2
npm run dev
```

`http://127.0.0.1:5173/keywords` → 검색광고 검색량 조회 → 키워드 입력 → 검색량 조회 버튼. API 서버는 4179, UI는 5173 포트다. 처음 검증용 `server/probe.ts`를 다시 실행할 필요는 없다. 서버 실행 자체는 네이버 호출을 하지 않는다.

검증 명령: `npm run check`, `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`, `npm run test:secrets`.

수정사항은 로컬 작업 트리에 남겼다. Phase 1 커밋과 기존 백업 브랜치는 유지했다. push·운영 배포·DNS 변경·API HUB 연결·Reviewman 수정·Phase 3 작업을 수행하지 않았다. Phase 2B 범위의 구현과 검증을 마쳤으며 다음 단계는 별도 명령을 기다린다.
