## 구현

1. 원본 제목을 보존하고 메인·세부 키워드를 분리한다. 예를 들어 `카카오뱅크 비상금대출 연장 가능성`의 메인은 `카카오뱅크 비상금대출`, 세부는 `카카오뱅크 비상금대출 연장`이다. 제목 기반 규칙 추론이며 AI가 만든 값이나 측정값으로 표시하지 않는다.
2. 목록에서 두 키워드의 검색량·블로그 API 결과 수·조회 상태를 비교한다. 데스크톱은 표, 모바일은 카드다. 상세 비교에서 PC·모바일·합계·카페 결과·출처·조회 시각을 함께 표시한다. 미조회·자료 부족·실패를 0으로 바꾸지 않는다.
3. `후보 빠른 분석`은 체크한 후보만 처리한다. 동일 키워드를 합치고 검색광고·블로그를 먼저 조회한다. 후보를 자동 선택하거나 입력·화면 이동만으로 대량 조회하지 않는다. 중단 버튼은 이후 요청을 막으며 이미 시작한 요청의 성공 결과는 보존한다.
4. 수집은 기본 10개, 사용자 지정 1~100개다. 최대 2개 주제의 지식iN·뉴스 요청에 수집량을 배분하고, 중복 제거 후 목표 수만큼 저장한다. API 결과 부족·중복 때문에 요청 개수보다 적을 수 있으며 이를 화면에 표시한다. 추가 페이지를 자동 반복하지 않는다. 쇼핑 카테고리는 기존 선택 기능을 유지한다.
5. 검색광고 응답에서 관련 키워드의 정확한 PC·모바일 행이 이미 제공됐다면 해당 키워드의 측정값으로 재사용한다. 메인 수치를 세부 수치에 복사하지 않는다. `<10` 등의 정확한 합계 미제공은 미확인으로 남는다.
6. 빠른 분석·상세 분석·실패 상태를 별도 로컬 저장소에 보존한다. 새로고침 후 목록에서 바로 표시하며 저장 자료는 자동 만료로 재호출하지 않는다. 상세 화면은 빠른 분석에서 빠진 카페·트렌드 등을 채운다. 재실행은 명시적 버튼으로만 하고 기존 5분 요청 캐시를 우선 사용한다.
7. 종합 추천, 세부 검색량, 세부 블로그 결과 수 오름차순, 수요/결과 수 비율, 최신 발굴순을 지원한다. 비율은 실험용 지표이며 실제 경쟁도·노출 확률이 아니다. 분모 0·결측이면 산정하지 않는다. 메인은 시장 맥락, 실제 발행 의도와 수요 평가는 세부 키워드를 기준으로 한다. 기존 25/25/20/15/15 가중치와 공식 확인 조건을 유지한다.
8. 원고 작업실에 원본 제목과 두 키워드, 구분된 측정값, 추천·확인·미확인 근거를 전달한다. 원고 대상 키워드는 세부 키워드다. 서버 원고 지침에도 검색량·API 결과 수를 본문에 삽입하지 않고 메인은 관련 문맥에서 자연스럽게 활용하도록 명시했다. 네이버 3계정·Reviewman과 명시적 생성 버튼은 유지한다.
9. 기존 주요 메뉴 4개와 접힌 고급 설정을 유지한다. 수집한 주제·개수·분야·기기·기간도 저장해 다시 입력하지 않게 한다. 추가 분석값과 설정은 전체 백업의 선택 필드로 포함하며, 구버전 백업을 복원해도 현재 발굴 자료를 지우지 않는다. 다른 탭에서 저장 자료가 바뀌면 덮어쓰지 않는다.

## 호출 제한과 보호

- 검색광고 기존 일 30회·최소 10초, HUB 기존 API별 일 30회·월 300회·최소 1초를 유지한다. 서버의 원자적 예약·인증 오류 차단이 최종 기준이다.
- 실행 전 예상 호출 상한을 표시하고, 실행 중 검색광고와 HUB별 남은 예산 및 진행률을 구분한다. 상태 조회는 NAVER 외부 호출이 아니다.
- 빠른 분석은 고유 키워드별 검색광고 최대 1회 + 블로그 최대 1회이며 저장 자료·캐시 적중 시 감소한다. 세부 키워드와 메인이 다르면 상세 분석은 검색광고 최대 2회 + HUB 5회(쇼핑 포함 6회)다.
- 순차 실행과 요청 간격 대기로 불필요한 429를 방지한다. 예산 부족·인증 실패·429·연결 오류 시 자동 재시도하지 않고 남은 후보를 보존한다. 실패한 키워드는 빠른 분석 재클릭만으로 자동 재시도하지 않는다.
- Worker의 변경은 검색 응답 개수 계약과 원고 지침에 한정한다. DB 스키마·예산·Secrets·Access·비용 승인·DNS는 변경하지 않는다.

## 남은 제약

- 제목만으로 세부 검색 의도를 완벽히 추출할 수는 없다. 원본 제목과 추론 키워드를 함께 표시한다.
- 실제 제공값이 없거나 정확한 합계가 없으면 미확인으로 남는다. 트렌드·Reviewman 적합성·공식 사실 확인이 부족하면 추가 조사 필요다.
- 저장 자료는 원래 조회 시각 기준이다. 최신 값이 필요하면 상세 화면에서 명시적으로 다시 실행해야 하며, 5분 요청 캐시는 유지한다.
- 브라우저 로컬 저장소를 사용한다. 저장 용량 부족 시 기존 자료를 보존하고 오류를 알린다. 정기 전체 백업으로 다른 기기로 옮길 수 있다.
- 기존 번들 크기 안내는 남아 있다. 본문 수집·실제 검색 순위·상위 노출·수익 보장은 제공하지 않는다.
