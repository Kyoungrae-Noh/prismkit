# Phase 2D 추가 요구사항 · 구현 범위

2026-10-19. 기존 Phase 0~2C 저장소·LIVE 조회·후보 관리 유지.

- `/publishing`: 저장 후보 검색량/의도/출처와 수동 경쟁 평가, 발행 판단, 중복 이력을 통합.
- 검색 URL·확인 날짜·환경·경쟁 게시물·품질·차별화 근거 입력/수정. 자동 검색 또는 AI 판독 없음.
- PNG/JPEG/WebP 캡처를 후보 ID와 키워드에 연결하고 미리보기/저장/삭제. 파일 512 KiB, 후보 3장, 전체 1.5 MiB, 2,000만 화소 제한.

- 동일/정규화/유사 의도/같은 주제/같은 Reviewman 페이지 경고. 다른 세부 의도는 별도 기획 가능.
- 실험 규칙은 근거와 미확인을 표시하고 수요만으로 발행 추천하지 않음. 계정 이력이 없으면 계정 확정하지 않음.
- `prismkit.publishing.v1` 독립 추가: 기존 글감/수동 분석/후보 스키마 및 값은 변경하지 않으므로 기존 데이터 변환 불필요. 새 키가 없으면 빈 v1 저장소로 읽는다. 알 수 없는 버전·손상 자료는 덮어쓰지 않는다. 향후 버전 변경에는 명시적 마이그레이션 필요.
- 브라우저 localStorage 저장, 용량 부족은 오류로 표시하고 기존 자료 보존. JSON 동일 ID 충돌은 전체 가져오기 거부.
- 실제 API 호출, 크롤링, API HUB, AI 생성, 발행 실행, Reviewman 수정, 배포/push/DNS 변경 제외.

# Prismkit SRS — Phase 1 기반 및 Phase 2C 추가

작성·확인일: 2026-10-19. 대상: `/Users/kkr/website/prismkit.online`.

## Phase 2C 추가 요구사항

Prismkit은 네이버 블로그 3개 계정의 발행 효율과 reviewman.kr 검색 유입·수익 개선을 위한 내부 도구다. Phase 2C는 이미 수신한 키워드의 로컬 필터링·규칙 분류·발행 전 후보 저장까지 다룬다. 실제 경쟁 분석, AI 생성, 자동 발행, Reviewman 운영 코드 변경은 포함하지 않는다.

- 7가지 검색 의도, 불명확/혼합/부정 맥락의 검토 필요 표시.
- 원문/PC/모바일/합계/출처/확인 시각 보존, 숫자·범위·누락 구분.
- 표기 중복 제거 및 원문 보존, 의미 단정 없는 유사 표현 그룹, 의도별 필터.
- 전체/PC/모바일 범위, 의도, 포함·제외, 상태 필터와 6가지 정렬. 낮은 수치를 삭제하지 않음.
- 1차 검토 추천·롱테일 후보·추가 검증 필요·제외 후보. 발행 확정·상위 노출 보장 없음.
- 단일/일괄 선택 저장, 중복 경고, 기존 글감 연결, 저장 복원, 후보 JSON 내보내기.
- 전체 수집/중복 제거 및 필터 적용 후 요약을 분리하고 API 호출 없이 500개 이상 처리.
- 기존 서버 호출/보안 제한을 그대로 유지하고 기존 53개 테스트 보존.

구현 기준과 결과는 [Phase 2C 보고서](PHASE2C_REPORT.md)를 따른다. 아래 Phase 1 범위 설명은 당시 요구사항 기록이다.

## 목적과 최종 워크플로

Prismkit은 글감 수집부터 키워드 검증, 콘텐츠 준비와 성과 관리를 지원하는 시스템이다. 기존 색상 도구와는 별개이며, 아래 전체 흐름은 최종 요구사항이다. Phase 1 완료를 전체 구현 완료로 해석하지 않는다.

1. 사용자가 여러 사이트에서 글감 캡처 수집
2. 캡처 이미지 업로드
3. AI가 글감·주제·핵심 키워드 추출
4. 글감별 시의성·검색 의도·수익화 가능성 평가
5. 네이버 자동완성·연관검색어 등을 통한 키워드 확장
6. 월간 PC·모바일 검색량 확인
7. 검색 결과 및 상위 블로그 경쟁 분석
8. 검색 수요·경쟁·차별화 가능성에 따른 발행 우선순위 결정
9. SEO·GEO·AEO 기반 원고 생성
10. 이미지 5장 및 네이버 발행 자료 준비
11. Reviewman 연결 및 UTM 관리
12. 발행 이력·성과 분석

## 데이터 의미

- `mode`는 자료 유입 방식(MANUAL / DEMO / API), `verification`은 검증 증거 수준이다. 수동 저장 성공이 API 검증 성공을 의미하지 않는다.
- 사용자 확인 날짜는 일 단위로 저장한다. 수집 시각을 알 수 없는 수동 자료의 `collectedAt`은 로컬 입력 저장 시각으로 정의하고 화면에도 저장 시각으로 표시한다.
- 기록 하나의 출처·날짜는 모든 입력값에 공통 적용된다. 다른 출처/시점의 값은 별도 기록으로 입력한다. 앞으로 API 필드별 provenance가 필요하면 모델을 확장한다.
- 검색광고 검색수는 최근 30일 기준이다. 데이터랩은 조회 범위 내 상대 지수이며 절대 검색량으로 환산하지 않는다.
- 블로그 API total은 해당 질의의 응답 수치, API 순서는 API 내부 순서다. 전체 문서 수·통합검색 실제 노출 순위와 동일시하지 않는다.
- 원문 본문이나 콘텐츠 품질 자료는 확보하지 않았다. 상위 콘텐츠 분석을 완료한 것처럼 표시하지 않는다.

## 비기능 및 제외 범위

React + TypeScript + Vite, 기존 로컬 저장과 UI를 유지한다. 320px·390px·1440px 화면에서 사용할 수 있어야 한다. 사용자 입력은 텍스트로 렌더링하며 HTML로 실행하지 않는다. 자격증명·원시 API 응답은 브라우저에 저장하지 않는다.

로그인/서버 저장/동기화는 미구현이다. 관리자용 운영 접근 제어는 향후 작업이며 현재는 로컬 프로토타입이다. 브라우저 자료 삭제 시 데이터가 사라진다. `.git`, 비밀 파일, 기존 배포 보존본, 다른 프로젝트를 수정·삭제하지 않는다.

원고·이미지 생성, 네이버 발행, Reviewman 운영 코드, 결제, 배포, DNS 변경, 원격 push, 비공식 검색 크롤링은 제외한다. Phase 2는 별도 지시 후 진행한다.
