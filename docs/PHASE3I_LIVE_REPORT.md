## 활성화와 보호

- `.env`의 HUB Client ID·Secret을 stdin으로 기존 `prismkit-searchad` Worker에 등록했다. 기존 Secret 4개와 기타 바인딩 보존을 확인했다. Cloudflare 관리 토큰은 런타임에 등록하지 않았다.
- 서버 정책 6종을 활성화했다. 키 누락·권한 실패 시 닫힌 상태를 유지한다. 401/403은 지속 차단, 429는 해당 KST 일 차단, 자동 재시도 없음. API별 일 30회·월 300회·최소 1초·동시 1개·최근 요청 5분 캐시를 유지한다.
- 글감 발굴 → 상세 분석 → 후보 선정 → 원고 제작 흐름과 주요 메뉴 4개를 유지한다. 고급 설정은 기본적으로 접혀 있다. 버튼 클릭만 외부 호출을 시작하며 입력·이동·필터는 호출하지 않는다. DEMO는 명시적으로 구분하고 유료 원고 후보에서 제외한다.
- 키워드 화면의 경쟁 분석은 이미 조회한 동일 키워드의 검색량을 재사용하고 블로그·카페·트렌드를 함께 표시한다. 부분 실패 시 성공 결과를 보존하고 미확인 검색량을 만들지 않는다. API 결과 순서·출처·제공 날짜와 상대 지표를 표시한다.
- 기존 후보·원고·이미지·발행 이력 저장 형식과 기존 예산을 유지한다. DNS, Access 정책, 다른 프로젝트, 비용 한도를 변경하지 않는다.

## 재개 중 발견하여 수정한 결함

1. Workers는 `redirect: 'error'`를 지원하지 않아 HUB 요청이 전송 전에 실패했다. `manual`로 바꾸고 3xx 응답을 실패 처리하여 인증정보가 다른 호스트로 전달되지 않도록 했다. 실제 workerd의 6종 성공 경로와 재시작 후 캐시·예산·인증 차단을 검증했다. [Cloudflare Request 규격](https://developers.cloudflare.com/workers/runtime-apis/request/).
2. 경쟁 분석 패널과 기존 후보 패널의 React key가 같아 패널이 중복될 수 있었다. 각 패널의 식별자를 분리하고 검색량 조회→키워드 변경→후보→원고 인계 테스트를 추가했다.
3. Wrangler 빌드 출력의 상대 경로 처리 차이를 없애도록 프로젝트 내부 절대 경로로 고정했다. 런타임 테스트가 방금 빌드한 Worker를 읽도록 확인했다.
