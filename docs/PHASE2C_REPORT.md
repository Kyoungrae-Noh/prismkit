## 2. 필터와 요약

- 수신한 LIVE 전체 행, 저장된 MANUAL 핵심 키워드, 기존 DEMO를 별도 모드로 분석한다. MANUAL 관련어에는 독립 검색량이 없으므로 그 검색량을 핵심 키워드에서 복제하지 않는다.
- 전체·PC·모바일 최소/최대, 검색 의도, 키워드 포함/제외, 후보 상태 필터. 전체 검색량 100/500/1,000/5,000 이상 빠른 설정과 사용자 지정 범위를 지원한다.
- 범위값 `<10`과 누락은 숫자 0으로 치환하지 않는다. 범위를 알 수 없는 자료는 기본적으로 별도 검토용으로 포함하며 체크 해제하면 수치 필터에서 숨긴다. 수치 기준을 충족했다고 간주한 것은 아니다.
- 낮은 수치 및 범위 밖 키워드는 원본에서 삭제하지 않는다. 제외어는 제외 후보로 표시하고 일반 결과에서는 숨긴다. 후보 상태를 제외 후보로 바꾸면 다시 볼 수 있다. 다른 범위/포함 필터는 계속 적용된다.
- 합계 내림차순/오름차순, PC 내림차순, 모바일 내림차순, 이름순, 1차 추천 우선순위. 정확한 수치가 없는 행은 수치 정렬 마지막에 둔다.
- 전체 수집 수·중복 제거 후 수·전체 수치 확인 가능 수를 표시한다. 별도 줄에 현재 필터 결과 수·수치 확인 가능 수·상태별 수를 표시한다. 숨긴 행을 삭제되거나 분석 실패한 것으로 집계하지 않는다.
- 50개씩 페이지를 표시하며 필터 결과 전체 선택은 모든 페이지에 적용한다. Phase 2B의 기존 상위 50개 LIVE 미리보기는 유지한다.

## 3. 검색 의도 rules-v1

| 유형        | 대표 규칙 표현                                           |
| ----------- | -------------------------------------------------------- |
| 정보 확인형 | 방법·하는법·뜻·대상·조건·기간·일정·사용처·자격·준비물    |
| 신청·접수형 | 신청·접수·등록                                           |
| 조회·확인형 | 조회·확인·잔액                                           |
| 예약·예매형 | 예약·예매                                                |
| 비교·선택형 | 비교·추천·차이·선택                                      |
| 구매·전환형 | 구매·구입·가격·할인·주문                                 |

명시적 행동 유형 하나가 있으면 정보 표현보다 우선한다. 복수 행동 유형이나 취소·환불·불가·제외 등의 맥락은 검토 필요로 남긴다. 형태소/문맥 모델이 아니므로 오분류 가능성이 있으며 실제 사용자의 검색 의도를 확정하지 않는다. AI 확장용 `IntentClassifier` 인터페이스만 정의했다. AI 호출은 없다.

## 4. 중복과 그룹

동일 모드·동일 출처 안에서 NFKC, 소문자화, 공백·장식 기호와 한글 사이 하이픈 정규화를 적용한다. C++/C#, 숫자 범위 등의 의미 기호는 유지한다. 서로 다른 모드/출처는 증거를 섞지 않도록 별도로 유지한다.

정규화 결과가 같은 행은 원문·수치·출처·시각을 `originals`에 보존하면서 하나의 후보로 묶는다. 수치가 충돌하면 대표 수치를 선택하거나 합산하지 않고 결측으로 두며 추가 검증 필요로 분류한다.

신청/접수, 구매/구입, 예약/예매, 방법/하는법 등 제한된 표현 치환과 동일 의도 규칙으로 유사 표현 그룹을 제안한다. **그룹 행은 삭제하지 않는다.** 조건·대상·취소 등의 잔여 표현이 다르면 다른 그룹이다. 유사 그룹에는 검토 필요를 붙이고, 기존 1차 추천도 추가 검증 필요로 낮춘다. 같은 의도는 의도 필터로 함께 볼 수 있다. 순수 문자열 유사도만으로 의미가 같다고 확정하지 않는다.

## 5. 1차 후보 기준

숫자 종합 점수나 상위 노출 확률은 만들지 않는다. 검색량은 출처 자료(수동/가상 자료는 해당 표시), 나머지는 규칙 추정이다. 연령은 입력받거나 가중치로 사용하지 않는다.

- **1차 검토 추천:** 의도 규칙이 명확하고 핵심 주제 및 사용자가 직접 지정한 Reviewman 연결 주제가 일치하며 정확한 양의 검색량이 있고, 수치 충돌/유사 그룹 중복 검토가 없는 경우. 경쟁 분석 완료가 아니다.
- **롱테일 후보:** 핵심 주제에 명확한 의도 표현이 추가된 구체적 키워드. 수치가 작거나 0·`<10`·누락이어도 보존한다. 연결 가능성을 추가로 확인해야 한다.
- **추가 검증 필요:** 의도 혼합/불명확, 주제 미설정/불일치, 수치 충돌, 유사 그룹 중복 등. 주제 일치는 부분 문자열 규칙이므로 불일치만으로 무관하다고 단정하지 않는다.
- **제외 후보:** 사용자가 지정한 제외어 일치. 낮은 검색량만으로 제외하지 않는다.

우선순위 정렬은 위 상태 순서로 묶고 같은 상태 안에서 확인 가능한 검색량 내림차순, 이름순을 사용한다. 100/500/1,000/5,000은 화면 필터 옵션일 뿐 추천 임계값이 아니다. Reviewman 연결어 일치는 실제 사이트 콘텐츠나 수익성 검증이 아니다. 발행 확정 상태는 없다.

## 6. 후보 저장과 기존 기능

단일 선택·전체 선택·선택 해제·일괄 저장을 지원한다. 조건/정렬/원본 변경 시 선택은 초기화되어 숨겨진 후보가 의도치 않게 저장되지 않는다. 선택 후보만 `prismkit.candidates.v1`에 기록한다.

저장 항목: 원문과 중복 원문, PC/모바일/합계, 출처·확인 시각, 모드, 의도·상태·판정 근거, 규칙 버전, 당시 핵심 주제·Reviewman 연결 주제, 저장 시각, 글감 ID. 동일 모드·정규화 키워드 중복 저장은 경고 후 건너뛰며 기존 자료를 덮어쓰지 않는다. 다른 모드의 같은 키워드도 중복 경고는 표시하지만 구분하여 저장할 수 있다.

기존 글감과 일괄 연결하거나 저장 후 연결/해제할 수 있다. 삭제된 글감 연결은 경고하며 해제 가능하다. JSON 내보내기로 후속 원고 제작 단계에 전달할 구조화 자료를 제공한다. 자동 원고 생성이나 JSON 가져오기는 없다.

저장 실패 시 선택을 유지하고 손상된 저장소는 자동 덮어쓰지 않는다. 브라우저 데이터 삭제 시 후보도 삭제되며 기기 간 동기화하지 않는다. LIVE 후보는 저장 당시의 실제 응답 스냅샷이지 현재 수치가 아니다.

기존 글감 CRUD·수동 입력·LIVE 조회·DEMO 화면과 서버의 5분 캐시/10초 간격/실행당 10회/오류 차단을 유지했다. API HUB·Reviewman 운영 코드·블로그 계정 설정은 건드리지 않았다.
