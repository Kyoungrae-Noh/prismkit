[네이버 검색 API 약관](https://developers.naver.com/products/terms/)에는 허용 범위를 벗어난 저장·AI 입력·수익화 제한이 있다. HUB 적용 계약이 동일하다고 단정하지 않는다. 신규 API 연결, 검색결과 본문 장기 저장, 검색 API 결과의 AI 전달은 승인 및 적용 조건 검토 전 구현하지 않는다. 현재 연결은 기존 검색광고만 유지하며, 신규 경쟁 자료는 사용자가 확인하고 적법하게 사용할 수 있는 근거를 수동 입력한다.

총 292개 시나리오를 검증했다: 단위·클라이언트 143, 서버 18, Edge 48, 실제 workerd/SQLite 런타임 5, Chrome E2E 78(데스크톱·390px·320px). 전체 실행에서 발견한 선택 상자/텍스트 영역 접근성 이름, 숨겨진 원문을 선택한 테스트, 모바일 생성 이력 버튼 가로 넘침을 수정한 뒤 영향받은 E2E 스위트를 재실행했다. 동작 중 포맷 변경으로 닫힌 기존 모바일 편집 대화상자도 안정된 소스에서 재검증했다. 수정 후 원고 E2E 6개와 기존 워크스페이스 시나리오가 통과했다. 단일 `check:all` 로그 하나가 무실패라고 주장하지 않으며, 전체 실행과 수정 후 해당 스위트 결과를 합산한 수다.

타입 검사, 프런트엔드 빌드, Worker/Pages Functions 빌드, 실제 로컬 Secret·canary의 Git/브라우저 번들 유출 검사 통과. 원고 서버의 Access·동일 출처·본문 크기, 승인 만료·일/월 한도·중복·동시 실행·429/timeout·예산 영속성과 이미지/네이버 분리를 모의 응답으로 검증했다. 실제 유료 OpenAI/네이버 API 호출은 0회다. 실제 원고의 문장 품질·운영 로그인 후 원고 생성 성공·블로그 편집기 붙여넣기 서식은 아직 검증하지 않았다.

배포는 기존 Worker를 먼저 갱신하고 Git main의 일반 Push로 기존 Pages 운영 자동 배포를 진행한다. 새 프로젝트·DNS·Access·Secrets 값 변경은 필요하지 않다. 공개 Worker와 pages.dev 보호, 관리자 JWT, 동일 출처 요청 검사를 유지한다. 실제 배포 ID·커밋과 사후 확인은 작업 완료 보고에 기록한다.
