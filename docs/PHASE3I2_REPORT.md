## 통합 분석

원본 제목과 조회용 핵심어를 분리한다. 예를 들어 `카카오뱅크 비상금대출 연장 가능성`은 제목을 보존하고 `카카오뱅크 비상금대출`로 분석한다. 기존 코드는 긴 제목에 가까운 문자열의 정확한 검색량을 찾았으며, 키워드 분석 화면에서는 기존 검색량 응답이 없으면 별도 조회를 요구했다. 이번 변경은 핵심어 추출과 자동 조회를 연결한다. 이것만으로 특정 키워드의 실제 검색량 제공을 보장하지는 않는다.

- 상세 분석 한 번에 검색광고 1회, HUB 블로그·카페·검색어트렌드 각 1회를 요청한다. 쇼핑 카테고리를 지정하면 쇼핑인사이트 1회가 추가된다.
- 검색광고의 정확히 일치하는 핵심어 행만 사용한다. 연관어의 큰 검색량으로 대체하지 않는다. `<10`, 미제공, 측정된 0을 구분한다.
- 블로그·카페 API 결과 수와 상위 표본의 제목·URL·제공일·요약·조회 시각을 표시한다. 통합검색 전체 문서 수·실제 순위·경쟁 난이도로 표시하지 않는다.
- 검색어트렌드는 요청 종료일까지 연속된 최근 14일을 인접한 7일 평균으로 비교한다. ±5%는 유사, 비교 자료 부족·기준 평균 0으로 변화율 산정 불가 시 보류한다. 상대 관심도이며 실제 검색량이 아니다.
- 경쟁 글 분석은 API 제목·요약에 한정한다. 포함어, 제공 날짜 기준 최신성, 규칙 기반 의도, 반복 소주제, 추가 확인할 정보 후보와 구성안을 로컬에서 만든다. 본문 수집과 실제 순위 추정은 하지 않는다.
- LIVE 확인·캐시·자료 부족·조회 실패·미조회를 구분한다. 재조회 실패 시 이전 성공 자료와 시각을 남기되 실패한 항목을 이번 평가 점수에 사용하지 않는다.

## 발행 평가와 화면

초기 가중치는 검색 수요 25%, 경쟁 환경 25%, 의도 20%, 트렌드 15%, Reviewman 15%다. 검증된 성과 모델이 아니다. 경쟁 환경 점수는 제목 표본의 핵심어 전체 포함 비율에 대한 차별화 가설이며 API 결과 수는 점수에 사용하지 않는다. Reviewman 적합성은 사용자 판단과 근거가 있을 때만 반영한다.

결측값은 0으로 대체하거나 가중치를 재배분하지 않는다. 확인 가중치와 해당 항목의 기여만 표시하고, 모든 평가 항목이 확인될 때 종합 점수를 표시한다. 필수 자료가 없으면 추가 조사 필요다. 정책·금융·부동산은 공식 출처·확인 내용·확인 시각 기록이 필요하다. 이는 사용자의 사실 대조 기록이며 URL만으로 공식 기관을 인증하거나 자동 검증했다고 주장하지 않는다. DEMO와 기존 주제 중복은 별도 보류한다.

목록은 제목·출처·검색량·블로그 결과 수·분석 상태·추천·상세 분석 버튼을 제공한다. 후보 저장·원고 제작·근거·재실행은 상세 화면에 모았다. 상세 근거·평가 입력·고급 설정은 기본적으로 접힌다. 기존 주요 메뉴 4개를 유지한다.

원고 작업실에 원본 제목, 핵심어, 수요, 경쟁 결과 수, 트렌드, 의도, 출처, 확인·미확인 사항, 추천과 공식 확인 기록을 전달한다. 실제 생성은 사용자가 별도 버튼을 눌러야 한다. 기존에 편집한 원고는 자동 덮어쓰지 않는다. 같은 분석 후보를 갱신하면 이전 후보 스냅샷을 이력으로 보존하며, 추가 메타데이터와 이력은 전체 백업·복원에 포함된다.

## 호출과 보호

- 클릭 전에 외부 호출 상한 4회/5회(DEMO 0회)를 표시한다. 기존 분석 열기는 추가 호출 0회다.
- 브라우저 메모리의 최대 30개·5분 캐시, 진행 중 동일 요청 병합, 기존 서버 캐시를 사용한다. 같은 핵심어의 최근 검색광고 응답을 재사용한다.
- 실패를 자동 재시도하지 않는다. 인증 실패·429 이후에도 자동 반복하지 않으며 재실행은 명시적 버튼으로만 한다.
- 기존 서버의 API별 속도·일간·월간 한도, Access·Secrets·비용 승인 설정을 유지한다.
- Worker·Pages Functions 소스와 영속 데이터 구조에는 변경이 없다. 기존 Worker 버전을 유지하며 프런트엔드는 기존 Pages Git 연동으로 배포한다.

## 검증과 한계

자동 검증은 모의 응답을 사용한다. 예시 대출 글감의 월간 12,000회, 블로그 6,008건, 카페 1,200건은 테스트 입력값이며 이번 작업으로 확인한 운영 수치가 아니다. 실제 운영 수치는 로그인 후 상세 분석을 실행했을 때 API가 제공하는 값을 따른다.

검증 대상은 핵심어 추출, 정확한 검색량 연결, 기간 비교, 제목·요약 분석, 결측·부분 실패, 가중치와 공식 확인 조건, 동시 요청 병합·캐시 만료, 후보 이력·전체 백업 복원, 한국어 입력, 원고 인계와 명시적 생성, API 제한·Access·비밀 보호다. 프런트엔드·서버리스 타입 검사와 빌드 및 비밀정보 검사를 포함한다.

- `npm run check`: 프런트엔드 165개, 서버 18개, Edge 70개 통과. 타입 검사와 프런트엔드 빌드 통과.
- `npm run test:runtime`: Worker·Pages Functions 빌드와 런타임 8개 통과.
- Chrome Playwright 전체 테스트: 데스크톱·모바일·소형 모바일 합계 108개 통과. 총 369개 테스트 통과.
- 최종 문구·URL 검증 보완 후 관련 단위 테스트 18개와 UI 테스트 12개 및 빌드 재검증 통과.
- 원고 화면의 발행 판단 근거도 통합 분석 스냅샷과 일치하도록 연결했다. 관련 UI·한국어 입력·기존 원고 인계 테스트 21개와 빌드 재검증 통과.
- `npm run test:secrets`: Git 대상 파일과 클라이언트 산출물의 실제 로컬 비밀값 미포함, canary 제외 및 `VITE_` 키 노출 차단 검증 통과.

실제 API 결과가 없거나 `<10`으로 제공되면 미확인/자료 부족이 남을 수 있다. 본문·실제 검색 순위·성과 예측은 제공하지 않는다. 인증된 운영 세션의 실제 조회는 추가 호출 제한을 지키기 위해 반복하지 않는다. 빌드에는 기존 단일 청크 크기 안내가 남아 있다.
